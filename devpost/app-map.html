The 3-stop code route

  1. Form → report. In src/app.js, search for source-form. Its submit listener calls analyzeSources, then renders the result. openEvidence builds the highlighted passage with text nodes.
  2. Uncertainty → disabled action. In src/analyzer.js, follow parseDates. An ambiguous zone produces instant: null. Back in renderDeadlines, the corresponding radio stays disabled.
  3. Selection → calendar. In src/export.js, selectedDeadline rejects an absent/unresolved choice. calendarEvent writes UTC, evidence and review warnings. foldLine respects UTF-8 byte limits.

To change this, start here

Supported dates or category matching

Edit src/analyzer.js; add an example and expected result to tests/analyzer.test.js. Preserve unresolved behavior for dates you cannot safely interpret.

Layout, labels or the synthetic fixtures

Start in index.html, src/styles.css or src/samples.js. Keep the synthetic label visible and test mobile layout when changing density.

Export contents or calendar behavior

Start in src/export.js and tests/export.test.js. Never remove warnings just because a deadline was selected.

A practice to reuse

Turn a vague promise into an observable boundary. “Handle timezones safely” became “CST must yield no instant and no calendar export.” The test in tests/analyzer.test.js and the real mobile browser check in docs/verification.md make that boundary inspectable. On another project, name one input that should make the system refuse to guess, then test both the function and the visible action.

Run it again
